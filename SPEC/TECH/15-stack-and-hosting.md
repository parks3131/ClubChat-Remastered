# Stack and hosting

| Layer | Decision | Rationale |
|---|---|---|
| **Client** | Expo (React Native) + Expo Router, iOS / Android / web | Unchanged. [Screen map](../PRD/15-screen-map.md) and [Design system](13-design-system.md) are real shipped work worth keeping. |
| **Local store** | `expo-sqlite` (OPFS on web) | Offline reads, outbox, cursors. |
| **Server language** | **TypeScript / Node 24** - *decided* | Shared types with the Expo client end-to-end. Node handles thousands of sockets comfortably at this scale. Elixir/Phoenix was the honest alternative (better under connection churn, the runtime WhatsApp itself uses); rejected because the transport we need is modest and the shared-contract win is daily. Revisit only if a load test disappoints. |
| **HTTP + WS** | Fastify (or Hono) + `ws` | Small, fast, no framework opinions to fight. |
| **Validation / contract** | Zod schemas shared between client and server | One definition per payload; the client cannot drift from the wire format. |
| **DB access** | Drizzle | SQL-shaped, typed, migrations as files. **A migration is never edited after being applied** ([Engineering pitfalls](14-engineering-pitfalls.md) 29). |
| **Database** | Postgres 17, managed (Neon / RDS / Fly Postgres) | Managed hosting was never the problem; putting logic in the DB was. |
| **Cache / bus** | Redis (Upstash or a managed instance) | Registry, pub/sub, rate limits. Never a source of truth. |
| **Event log** | Kafka, downstream of the outbox - *decided* | Durable replayable event log with independent consumer groups. Explicitly a learning goal, not a scaling requirement; recorded as such in [Effects engine](04-effects-engine.md). Redpanda or Kafka in Docker for local dev. **Hosted provider still open - see [decisions/](../decisions/).** |
| **Object storage** | S3-compatible (Cloudflare R2 recommended - zero egress) + CDN | Media egress is the dominant variable cost. |
| **Auth** | `better-auth`, self-hosted, in our Postgres - *decided* | Email/password only. Identity in our own Postgres keeps the entire domain in one transactional store, which matters most for account deletion: anonymise + block future sign-in becomes one transaction rather than a two-system dance. We own password reset and email deliverability. |
| **Outbound mail** | A `Mailer` port - [ADR-0019](../decisions/0019-outbound-mail-is-a-port-with-a-deferred-provider.md) - with **Resend** behind it - [ADR-0020](../decisions/0020-resend-is-the-mail-provider.md) | One method, `send`. Production runs `ResendMailer`, a single `POST https://api.resend.com/emails` with no SDK. Development and CI run `LoggingMailer`, which writes the message and its reset URL to the process logger; tests run `RecordingMailer` and assert on it. Which one the API builds is decided by `RESEND_API_KEY` being present, and `MAIL_FROM` must accompany it or startup fails. **The API refuses to boot in production without a real transport** - that guard is what stops the log-only path shipping. |
| **Push** | Expo Push Service → APNs / FCM | One adapter, three platforms. |
| **Error monitoring** | Sentry. `@sentry/node` on the three server roles, `@sentry/react-native` on the phone - **two projects, not one**, because Sentry projects are platform-typed and a React Native project gets source maps, release health and a crash UI a Node project does not | [Roadmap and open questions](../PRD/17-roadmap-and-open-questions.md) listed its absence as release-blocking. Server closed 2026-08-03, client 2026-08-12. **Not** "from day one" as this row claimed for the life of the project: it was written from the plan and stayed there while no commit had it. The version on the phone is pinned by Expo (7.11), not npm's latest - the same trap as TypeScript 6 in `AGENTS.md` 5.1 |
| **Hosting** | Gateway + API + Worker on **Fly.io**; web client on Vercel - *decided* | The gateway holds long-lived connections and needs a long-running process. Postgres colocated on Fly (or Neon in the same region); Redis via Upstash. |
| **Testing** | Vitest; a table-driven permission-matrix suite; Testcontainers Postgres for handler tests | [Roadmap and open questions](../PRD/17-roadmap-and-open-questions.md): the matrix is hand-verified today. That ends. |
