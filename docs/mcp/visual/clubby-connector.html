There are three roles in MCP. Two of them already exist and belong to Anthropic. We only build the third, so there is no client for us to write.

MCP server · we build it ClubChat /mcp

A new entrance on our existing API. Answers with what you are allowed to see, and nothing else.

Where it fits

Inside the API

A new entrance, the same building behind it. The two paths only differ at the top and in one middle step. Everything that decides what you may see is shared, so Clubby can never see more than the app shows you.

The rules

Clubby acts as you

It sees exactly what you see in the app. If you can't open a chat, neither can Clubby.

Read-only, enforced twice

There are no write tools, and the token itself only allows reading. A "send" tool added by mistake later would still be refused for every existing connection.

Stops the moment you're suspended

The account check runs on every question, not only at sign-in. A suspended or deleted account stops working on its next question.

Marks nothing as read

Unread counts decide who gets a push. Clubby reading a chat must not silence notifications you never saw.

Direct messages included

Your call, 18 Oct. Clubby reads your own conversations, the same ones you can open in the app, and nobody else's.

Says where your data goes

What Clubby reads, direct messages included, is sent to Anthropic to answer you. The Allow page says so, and the privacy policy gets a line.

Build order

Each step is tested and committed before the next one starts.

  1. Upgrade the sign-in library

    better-auth from 1.6.25 to 1.7.10, on its own. It sits under every request, so sign-in, sign-out and password reset get checked on the phone before anything is added.

  2. Two small clean-ups

    The channel permission check and the calendar sorting move to where both the app and Clubby can call the same code. Nothing the app does changes.

  3. Sign-in for Claude

    The OAuth pieces, one database migration for tokens, the two "where to sign in" addresses, and the sign-in and Allow pages.

  4. Proves the chain

    One tool, all the way to your phone

    Only list_my_clubs. Deploy it, add ClubChat at claude.ai, then ask in the Claude phone app twice: once with the dictation mic, once in hands-free voice mode. Everything is proved end to end before twelve more tools get written.

  5. The other twelve tools

    Each one starts with a failing test against the seeded Binghamton Running Club.

  6. Prove the locks

    Try to read another member's club, use a suspended account, use a wrong or expired token, and read somebody else's direct messages. Watch each one get refused.

  7. Write it down

    Product and technical spec pages, three decision records, the privacy line.

New, reused, not built

New

  • /mcp entrance and 13 tools
  • Sign-in and Allow pages
  • Token tables, one migration
  • Server packages only, so the phone app needs no new build

Reused as is

  • Every read function
  • Policy rules
  • Account check and rate limit
  • Fly, Postgres, Redis, R2

Not built in stage one

  • An MCP client (Claude is the client)
  • Anything that sends or changes
  • A mic button inside ClubChat
  • "Hey Siri, ask ClubChat"

Settled

  1. Direct messages are in.
  2. Typing or the dictation mic works with connectors. Dictation turns speech into text before Claude sees it. The only unknown is hands-free voice mode, where Claude talks back. That decides whether Clubby is hands-free in the car, not whether it works. Step 3 checks it.
  3. Claude Pro is enough. You add ClubChat once at claude.ai in a browser, and it then shows up in the phone app.
